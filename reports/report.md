### 4.4. Дефекты уровня набора и межтребовательные противоречия

- **D-004** ⛔ **Blocker** · Противоречие · 📍 стр. 171
  - **Цитата:** «{"result":"ERROR","message":"Проверьте сумму"}»
  - **Почему это дефект:** Ошибка бизнес-валидации возвращается с HTTP-статусом успеха (2xx) и result=ERROR, при этом для неверных параметров уже объявлен 400. Клиент и мониторинг не смогут однозначно отличить успех от отказа; два способа сообщить об одной ошибке противоречат друг другу.
  - **Критерий:** IEEE 830 §4.3.4 consistent; RFC 9110 §15; ISO/IEC/IEEE 29148 §5.2.6 consistent; RFC 9110 §15.2.1, RFC 9457
  - **Как исправить:** Возвращать 400/422 с единым форматом ошибки (например, RFC 9457 problem+json: code, message, field); 200 — только при успешном сохранении.
  - <sub>Источник: правило `API-200-WITH-ERROR` · подтверждено LLM · объединено находок: 2 (API-200-WITH-ERROR, LLM QualityFilter) · цитата: точное совпадение</sub>

- **D-005** 🔴 **Critical** · Противоречие · 📍 стр. 189
  - **Цитата:** «Для чужой карты возвращается 404, как и для отсутствующей карты.»
  - **Почему это дефект:** В секции статусов объявлен код 403 для доступа к ресурсу, а в тексте особых правил указан код 404, что создает противоречие в контракте API.
  - **Критерий:** ISO/IEC/IEEE 29148:2018 §5.2.6; IEEE 830 §4.3.4 consistent; ISO/IEC/IEEE 29148 §5.2.6 consistent
  - **Как исправить:** Унифицировать код ошибки для чужой карты во всех разделах спецификации REST API (например, зафиксировать 403 или 404).
  - <sub>Источник: LLM · QualityFilter `API-STATUS-CONTRADICTION` · объединено находок: 2 (API-STATUS-CONTRADICTION, LLM QualityFilter) · цитата: точное совпадение</sub>
